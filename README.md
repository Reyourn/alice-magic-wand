# 爱丽丝的魔杖

Alice's Magic Wand · 本地多 Agent 协作工作台

在本机浏览器中协调 **Codex、Claude Code、WorkBuddy**：配置连接与模型、组建专业团队、确认任务计划、观察执行，并随时中断纠正或人工接管。

**本项目由维护者用于开源学习、研究与技术参考，不作为商业产品运营。该用途声明不改变 MIT 许可；MIT 仍允许商业使用，第三方许可各自有效。**

项目处于持续开发阶段。已实现的功能与模拟测试不等于三种原生工具的完整协作验收；跨工具返工、整合与交付仍需在使用者自己的环境中验证。仓库不包含账号、API Key、运行数据库、业务项目或历史会话。

## 能做什么

- **工具接入**：检测原生运行程序，管理原生认证、官方 API 与兼容网关连接；成员独立选择连接及模型。
- **团队与会话**：主控、开发、审查、测试、数据分析等角色模板；实时消息、附件、权限审批、中断纠正与人工接管。
- **计划编排**：任务依赖画布、计划确认、执行轮次、暂停、返工和待处理事项。
- **成果与交付**：关联 Git 工作树、提交、测试和审查版本；办公输入快照、成果预览，以及需要明确确认的交付动作。
- **本机能力**：绑定本地 stdio MCP、技能或脚本；区分发现、连接与真实调用验证。
- **用量记录**：保存原生回执中的 Token；缺失值保持未知，不据此猜算费用。

前端使用 React、TypeScript 和 React Flow；本地后台使用 Fastify、SQLite、Beads 与 Git。服务仅监听 `127.0.0.1`，当前重点支持 **Windows 桌面浏览器**，不是多用户或公网服务。

## 快速启动

准备 **Node.js 24（含 npm）** 和 **Git**。创建及管理任务还需要可用的 **Beads CLI（`bd`）**；执行 Agent 任务需要自行安装相应原生工具并完成认证。

```powershell
git clone https://github.com/Reyourn/alice-magic-wand.git
cd alice-magic-wand
npm ci
npm run build
npm start
```

在浏览器打开 [http://127.0.0.1:4310](http://127.0.0.1:4310)。保持服务终端运行；终端中的 `Ctrl + C` 会结束后台服务。Windows 也可双击 `Start-Workbench.cmd`；它会检查依赖、构建并尝试打开浏览器。

首次使用顺序为：**接入中心 → 配置并验证连接 → 接入项目 → 创建团队 → 提交目标 → 核对并确认计划**。仅检测到工具或模型目录，不代表认证成功或模型可调用。调用验证会使用所选服务的额度。

详细步骤、环境变量和 WorkBuddy 两版登录说明见 [启动与配置](docs/getting-started.md)。

## 开发与验证

```powershell
npm run typecheck
npm run build
npm test -- --maxWorkers=2
```

开发时在两个终端分别运行 `npm run dev` 与 `npm run dev:ui`，网页开发服务器使用 `4311`，API 使用 `4310`。测试主要使用可控适配器和临时文件；部分用例会操作临时 Git 仓库，真实 Beads 用例在未检测到 CLI 时跳过。上述命令不会替代原生 Agent 的真实验收。

`scripts/validate-*.ts` 中的原生验证脚本可能启动工具、打开授权页或产生模型调用用量。运行前先阅读脚本，在自己的隔离目录中明确选择连接，不将探针当作默认安装步骤。

## 使用边界

- 工作台管理自己启动的会话，不导入原生桌面历史；WorkBuddy 会话不保证出现在其桌面侧栏。
- 国内版与国际版 WorkBuddy 按不同产品和认证入口处理；桌面已登录不代表内置 CLI 已登录。部分版本要求每个受控进程单独授权，等待窗口也受原生 CLI 限制。
- 模型、图片、MCP 与用量能力取决于实际工具、连接和服务；配置发现、调用验证与最终运行回执分别展示。
- 默认一个主控、最多三个普通成员并行。中断保留已经产生的代码与成果；停止回执未知时须先核对，不能直接启动第二个写者。
- 关闭网页不会停止仍在运行的后台任务。后台服务重启后的未确认轮次需要核对，不应盲目重复派发。
- 凭据通过原生工具或接入中心在本机配置。新增 API Key 使用 Windows DPAPI 保存；公开仓库不附带任何凭据。不要上传自己的数据目录、日志、附件或授权回调地址。
